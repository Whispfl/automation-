### Initial unopened egg

The 6.5-stud geometry is measured to the attached original Prompt, not substituted with the physical travel Root radius.

`ReplicatedStorage.Client.Gui.ProximityPrompt:21-51` adds each actual engine prompt to `_cache`; Destroying removes it. The constructor sets HoldDuration=0, RequiresLineOfSight=false, custom Style and OnePerButton exclusivity (29-34). Native Visible counts PromptShown and PromptHidden across the service (88-106). A prompt attached to another original, disabled/unparented prompt, same-name ActionText alone or stale cache entry is insufficient selected-instance proof.

### Opened ordinary egg

`ClientScript:869-885` checks alive character, actual root and current LocalData. If `ProximityPrompt.Visible == 0`, it scans **all exact private registry keys, across egg names**. A candidate must have Root 3D distance <=16 and Unlocked truthy. The scanner retains the candidate with strictly smaller distance at 882-883. It is not a nearest-same-name scanner. Equal-distance ties inherit registry iteration order, which is not an exported stable contract; OC should block an unresolved tie rather than invent an ordering.

At 937-955 it attaches LootPoolViewer to the selected original Prompt and renders that original's named pool. Activation closes over the selected original (959-1036). At 1054-1055 it updates the active original and clears auto mode when the nearest selection changes.

Consequently, supported opened-egg verification requires the retained selected original to be the uniquely nearest eligible registered original under this exact radius/Unlocked/global-visibility rule. Another eligible egg, including a different name, that is closer or tied blocks the selected hatch. An unloaded/replaced selected instance, stale membership/geometry, unavailable native visibility or incomplete competing-original evidence remains a precise blocker. This is an inference from exposed client selection behavior, not proof of the server's own selection algorithm.
